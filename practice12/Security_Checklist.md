# Practice 12 security checklist

| Perspective and item | React code-based | Appsmith Community | Remaining risk and verification |
|---|---|---|---|
| SAST – validation | Reviewed the Practice 12 wrapper, existing engine, and React form. Strict parsing and bounded whole minutes precede blocked/overlap checks. | Reviewed the exported JS object, input bindings, button action and result expression. It applies the same precedence. | Rule copies could diverge. Replay the frozen cases and edge cases on both apps after any rule change. |
| SAST – XSS, injection and output | React renders fixed feedback strings as text. No HTML injection API, dynamic evaluation, database query or command execution was added. | A native Text widget can handle markup, but the app constructs feedback from literal messages and codes. User text is parsed and compared with the input snapshot, and the table receives only fixed fixture data. No user text is evaluated as JavaScript or sent as SQL. | Future bindings could surface untrusted data. Review Text and event expressions in any new export and repeat the harmless input probes. |
| SAST – credentials and data | The Practice 12 files require no credentials or student data. The existing package declares Supabase, but the app source does not use it. | No datasources, custom libraries, credentials or personal booking data in the export. The local administrator account belongs to the container, outside the export. | Keep the builder's account data out of screenshots and repository files. Inspect any later export for added connectors and credential fields. |
| DAST – validation and handling | 9/9 browser probes passed, including empty start/duration, malformed time, fractional duration, harmless HTML-like text in both fields, equal-to-clock precedence, day boundary and exactly 120 minutes. | 9/9 of the same probes passed through the live Appsmith Preview of the native app, and again on the re-import. | Probes cover the visible behavior of these specific builds. No external service scanning or exploit testing was performed. |
| DAST – data integrity | T8 compares the visible row values before and after T1–T7. The older code regression also verifies all five fixtures and storage. | T8 compares the visible row values before and after T1–T7. The export has no booking write action, and the result is stored in browser session memory using nonpersistent `storeValue`. | The check is specific to the fictional data and the observed routes. Repeat with any future write-capable product feature. |
| SCA – dependency audit | `npm audit --json` exited 1 with 25 affected packages (2 low, 7 moderate, 14 high, 2 critical). `npm audit --omit=dev --json` exited 1 with one high finding, `ws`. Practice 10 recorded the same totals. Vitest and Tinypool are the critical entries. | Appsmith Community v2.7.2 image and digest recorded. There are zero extra datasources and zero custom JS libraries. The app export does not list the platform's dependency tree. | Code maintainer owns dependency upgrades, lockfile and CI retests. Appsmith ships platform fixes. The self-host operator owns image updates, backups and re-import/replay checks. A platform-wide image SBOM audit and Cloud internals were outside this review. |
| Permissions – editor/viewer and public exposure | Current published static demo displays fictional data. Practice 12 was tested on loopback. The prior GitHub repository is public and the new branch is local. | The app's Share panel showed public access off, matching `isPublic: false` in its export. A signed-out Chrome session was redirected to the local login with no editor visible. The isolated editor was accessed using the local administrator. No extra users or roles were granted. | The viewer role was not tested with a separate account. Before sharing, verify with signed-out and viewer sessions that published viewing and editor authorization work as intended. |
| Permissions – connectors and least privilege | No external integration is called by the Practice 12 checker. | Native widgets use one JS object, no query or connector actions. The Docker port listens on loopback. | Review grants and scopes if real data are added. Limit editor roles and verify public exposure separately before changing sharing. |
