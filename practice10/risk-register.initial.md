## Score justification and priority

**R1 — 2 × 2 = 4.** Skipping manual checks is possible. The exact fresh-run barrier is reproduced. Impact is moderate because wrong feedback affects a fictional demo, without real bookings.

**R2 — 2 × 2 = 4.** The safeguards are absent, but no unauthorized action is observed. Moderate impact is appropriate for this small repository and preserved Git history.

**R3 — 2 × 2 = 4.** Affected versions and permissive HTTP behavior are observed. No exploit is attempted; UI/API server conditions are not used by npm test. Supabase is not imported by app source. These checks do not establish a vulnerability in the static published bundle.

**R4 — 2 × 1 = 2.** The omission is reproduced. Current 81 tests still run; impact is minor for the present fixed suite and review can require explicit collection.

**R5 — 2 × 1 = 2.** The stale context exists. Core run commands work, and no behavior failure is observed, so impact stays minor.

**R6 — 1 × 1 = 1.** The helper edge is observed, but acceptance for out-of-domain callers is unspecified and the normal UI does not supply it. This is not established as an AC violation.

**R7 — 1 × 2 = 2.** Score is for the hypothetical consequence only. No present defect is found; it is not an actionable confirmed risk.

**R8 — 1 × 2 = 2.** No supporting path or credential is found. The sample scan is not a full secret audit and does not certify all files/history.

R1 and R2 are selected among the three equal-score confirmed findings. R1 removes the reproduced verification barrier and makes evidence repeatable; R2 supplies the explicit agent review/isolation controls required by this exercise. R3 remains a separately owned security item: the audit does not pretend that CI or documentation upgrades dependency versions. A toolchain upgrade may cross major versions and needs its own compatibility review. No residual reduction is recorded before the selected patches are approved, applied and tested.
