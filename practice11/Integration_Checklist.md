# Integration checklist for the existing Smart Campus project

1. Review the local commit and `practice11/evidence/final/source.patch`. Review the recorded findings, the local test results and the Practice 10 dependency decision. Keep the existing `bdaniyar/boltnewproject` repository and Bolt project.
2. With push approval, fetch `origin`, check the ancestry and compare `git diff origin/main...practice11/explain-availability`. If `main` has advanced, integrate the new base into the feature branch, review the combined diff and repeat verification.
3. With authorization, push the feature branch using `git push -u origin practice11/explain-availability`. Open a PR with base `main`, head `practice11/explain-availability` and body `practice11/Pull_Request.md`.
4. Wait for human review and **Verify Smart Campus** on GitHub. Confirm the expected tests run, inspect the advisory artifact and confirm the merge candidate matches the verified source. Merge only after separate approval. Record the resulting `main` SHA.
5. Open the existing [Smart Campus Room Checker project](https://bolt.new/~/sb1-jsmjbzmo) and read its GitHub status. Its last observed editor branch was `practice08-experiment-baseline`. Verify the active branch and sync status. Resolve any branch mismatch only with separate approval, using the existing project. Check that the synced preview matches the merged feature source and passes desktop and mobile smoke checks for ordinary bookings, overlap, touching endpoints, blocked rooms and explanations.
6. Record the previous published version if Bolt exposes it. With publication approval, use **Publish → Update** inside the same Bolt project. Verify the feature and existing booking behavior at [the current public URL](https://smart-campus-room-ch-50zs.bolt.host/). Save the resulting deployment evidence for the course submission.
